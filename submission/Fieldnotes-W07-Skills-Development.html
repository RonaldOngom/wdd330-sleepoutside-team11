Project overview

Fieldnotes is a responsive trip-planning experience for people preparing to spend time outdoors. A visitor can search for a place, review current conditions and a seven-day forecast, check air quality and daylight details, save places for later, and personalize temperature units and theme. The interface is populated from live Open-Meteo JSON responses.

1:50–2:40 Show the interactions and localStorage behavior. “I can save this place with the star and return to it from my shortlist. I can switch from Celsius to Fahrenheit; the wind display changes from kilometres per hour to miles per hour along with the temperature display. I can also switch the color theme and refresh the forecast. The saved place, selected unit, theme, and last viewed place are stored in this browser. After reload, those preferences are restored.”
2:40–3:30 Show src/fieldnotes/api.js. “The API integration layer uses three Open-Meteo endpoints: Geocoding for place search, Forecast for current and daily weather, and Air Quality for AQI data. In getTripConditions, Promise.allSettled starts the forecast and air-quality requests concurrently. I check the forecast result separately: if the forecast fails, the app reports an error; if only air quality fails, the forecast remains available and the AQI is treated as unavailable. The fetch helper also checks HTTP errors and applies a timeout.”
3:30–4:20 Show src/fieldnotes/app.js. “This file turns the returned JSON into the interface. The daily arrays are mapped into seven forecast cards, and current and daily data are used for the condition details. The requestId protects the page when requests overlap: every new forecast request increments the ID, and after each asynchronous request the code compares its saved ID with the current one. If they differ, that response is stale and is ignored, so an older search cannot overwrite a newer result.”
4:20–4:45 Show src/fieldnotes/styles.css. “The CSS provides responsive layouts, light and dark themes, hover and focus feedback, and loading and entrance animations. Reduced-motion preferences are supported for visitors who prefer less animation.”
